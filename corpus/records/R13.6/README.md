# R13.6 — assessment to solver-operated return service

Recipient reconstruction says a solver whose timed-test answers were accepted received a Cicada-signed instruction to write a TCP server alone, expose it as a Tor hidden service and send its onion and port by GPG-encrypted email. The protocol required `WELCOME`, `RAND`, `QUINE`, `BASE29`, `CODE`, `KOAN`, Diffie–Hellman, `NEXT` and `GOODBYE`. `NEXT` acknowledged and recorded arbitrary text supplied by Cicada's client, making the solver's service the next-stage receiver.

A [December 2013 mirror](https://gist.github.com/navinpai/7837596/98b383923095465ba02432ffc6be06c4a877b2b9) preserves the command grammar as contemporary secondary evidence; its [local source record](sources/tcp-server-mirror.md) pins the bytes and provenance. An unsigned reported server log places `NEXT` around a signed-looking recruitment letter, but no authenticated callback packet survives.

The solver-operated receiver and missing callback state are the surviving boundary of the 2013 private route. The signed instruction bytes, recipient binding, complete service log and downstream private route are unavailable. Recipient-operated hidden services recur with a different HTTP protocol in R14.6.
